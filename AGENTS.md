# AGENTS.md — Ultix

Guidance for AI coding agents (and humans) working **inside this repository**.

Ultix is a personal, declarative **NixOS Stable flake** for two machines: a Zen 4 AMD desktop and an AMD/NVIDIA TUXEDO laptop. It layers:

- **Hyprland** (via UWSM) + **Noctalia v5** shell as the desktop session,
- **disko** (GPT → LUKS → Btrfs subvolumes) for declarative partitioning,
- an **impermanence** setup where `/` is wiped on every boot and `/persist` holds state,
- **Home Manager** for the user `fumoctl`,
- gaming (Steam, proton-cachyos/GE, gamescope, mangohud, lsfg-vk) and container/dev tooling (Docker, rootless Podman, `kind`, libvirt).

This file documents the architecture, conventions, and the traps that have actually bitten this config. **Read it fully before editing.** Every claim about evaluated values below was verified by evaluating the flake, not just by reading the source.

## 2. Hosts and targets

```text
nixosConfigurations.fumonix-desktop   # x86_64-linux, Ryzen 7600X (Zen 4), AMD GPU
nixosConfigurations.fumonix-laptop    # x86_64-linux, TUXEDO, AMD iGPU + NVIDIA dGPU (PRIME offload)
```

| Aspect | `fumonix-desktop` | `fumonix-laptop` |
|---|---|---|
| System | **x86_64-linux** | **x86_64-linux** |
| Kernel | `linuxPackages_cachyos-lto-znver4` (fallback `linuxPackages_latest`); verified 7.3.0 | same base + `.extend` overriding `tuxedo-drivers.pahole` |
| GPU | AMD (`amdgpu` in initrd, `modesetting`) | AMD `amdgpu` + NVIDIA (`modesetting` + `nvidia`) |

| Hostname | `fumonix-desktop` | `fumonix-laptop` |
| State dir | `/persist` | `/persist` (same layout) |

Both hosts share users, the `/persist` layout, the container stack, the session, and the Home Manager profile. Put host-specific behaviour in `hosts/<host>/*.nix` — not in `common.nix` — unless it is genuinely universal.

> There is exactly one architecture (`x86_64-linux`) used for both hosts and for Home Manager. Do not introduce per-arch abstractions (aarch64 branches, `flake-utils.eachSystem`, etc.) unless explicitly asked.

## 3. Module wiring (how a host is assembled)

`flake.nix` creates each host with:

```nix
nixpkgs.lib.nixosSystem {
  inherit system;                       # x86_64-linux
  specialArgs = { inherit inputs; };    # every module can take `inputs`
  modules = [
    disko.nixosModules.disko
    home-manager.nixosModules.home-manager
    nix-flatpak.nixosModules.nix-flatpak
    chaotic.nixosModules.nyx-cache      # adds the Chaotic cache substituter
    chaotic.nixosModules.nyx-overlay
    chaotic.nixosModules.nyx-registry
    ./hosts/desktop/default.nix         # or ./hosts/laptop/default.nix
  ];
}
```

`hosts/<host>/default.nix` imports, in order:

```nix
[ ../common.nix ../containers.nix ./containers.nix ./hardware-configuration.nix ./disko.nix ]
```

`hosts/common.nix` imports `impermanence.nixosModules.impermanence` and `noctalia.nixosModules.default`, and ends by wiring Home Manager:

```nix
home-manager = {
  useGlobalPkgs = true;                 # HM packages come from the system pkgs (incl. overlays)
  useUserPackages = true;
  extraSpecialArgs = { inherit inputs; };
  users.fumoctl = import ../home;
  backupFileExtension = "backup";       # conflicting files become <file>.backup
};
```

`home/default.nix` imports:

```nix
[ inputs.nix-flatpak.homeManagerModules.nix-flatpak ./noctalia.nix ./shell.nix ]
```

and `home/noctalia.nix` imports `inputs.noctalia.homeModules.default`.

**Rule of thumb:** a *system* option goes in `hosts/common.nix` (shared) or `hosts/<host>/default.nix` (machine-specific). A *user* option goes in `home/*.nix`. A *package* goes in `environment.systemPackages` (`common.nix`, system-wide, available to all sessions and root) or `home.packages` (`home/shell.nix` / `home/noctalia.nix`).

## 5. Storage, impermanence, and boot (the most delicate area)

### Disk layout (`hosts/<host>/disko.nix` — identical on both hosts)

```text
/dev/disk/by-id/<disk>                  GPT
├── ESP            1G   EF00  → vfat, mount /boot, umask=0077
└── luks           100%        → LUKS name "crypted" → btrfs (-f)
    ├── @            → /              compress=zstd,noatime   (RECREATED EMPTY ON EVERY BOOT)
    ├── @persist     → /persist       compress=zstd,noatime
    ├── @nix         → /nix           compress=zstd,noatime
    ├── @log         → /var/log       compress=zstd,noatime
    ├── @snapshots   → /.snapshots    compress=zstd,noatime
    └── @swap        → /.swapvol      noatime,nodatacow  + 32G swapfile
```

Current disk IDs (re-check with `ls -l /dev/disk/by-id/` before any reinstall):

- desktop: `/dev/disk/by-id/nvme-UPULTR7K-4TSD_UPULTR7K4T25090017`
- laptop: `/dev/disk/by-id/nvme-WD_Blue_SN5100_1TB_25453U402530`

disko references partitions by **label** at runtime (`/dev/disk/by-partlabel/disk-main-ESP`, `disk-main-luks`), so `hardware-configuration.nix` deliberately contains **no `fileSystems`** (disko generates them). Never duplicate `fileSystems` entries there.

The `@swap` subvolume is mounted at `/.swapvol`; swap lives at `/.swapvol/swapfile` (32G). On a fresh install you must `swapon` it manually before `nixos-install` (see README).

### Ephemeral root (`hosts/common.nix`)

- `/nix`, `/persist`, and `/var/log` are marked `neededForBoot = true` and are mounted with `x-initrd.mount` (verified in the evaluated `fileSystems`).
- `boot.initrd.systemd.initrdBin = [ btrfs-progs coreutils gnused util-linux ]` makes those tools available in the systemd-based initrd.
- `boot.initrd.systemd.services.impermanence-clean-root` (verified present: `wantedBy = initrd.target`, `after = dev-mapper-crypted.device`, `before = sysroot.mount`):
  1. mounts the top-level subvolume (`subvolid=5`) of `/dev/mapper/crypted` at `/btrfs_tmp`,
  2. recursively deletes every nested subvolume of `@` (`btrfs subvolume list -o` piped through `sed`, sorted `-r`),
  3. deletes `@`,
  4. recreates an empty `@`,
  5. unmounts.

  Then the normal root mount (`sysroot.mount`, `subvol=@`) finds an empty root and impermanence bind-mounts everything back from `/persist`.

**`/etc/ly/save.txt` is persisted and `services.displayManager.ly` is the login manager.** If you replace the display manager, update the persistence list *and* `security.pam.services.ly.enableGnomeKeyring`, or the keyring will not auto-unlock.

### What survives a reboot

Declared in `environment.persistence."/persist"` (`hideMounts = true`, `allowTrash = true`):

- **System dirs**: `/etc/NetworkManager/system-connections`, `/var/lib/{AccountsService,NetworkManager,bluetooth,containers,docker,flatpak,libvirt,nixos,systemd,sbctl}`
- **System files**: `/etc/machine-id`, `/etc/ly/save.txt`
- **User `fumoctl` dirs**: Home XDG dirs (`Desktop`, `Documents`, `Downloads`, `Music`, `Pictures`, `Public`, `Templates`, `Videos`, `Projects`, `Games`, `Applications`), plus app state: `.config/{BraveSoftware,Code,VSCodium,equibop,dconf,gh,lsfg-vk,containers,com.github.githubapp,Antigravity,MangoHud,xfce4,AmneziaVPN.ORG,"Podman Desktop",.android,"AbacusAI Desktop",abacusai-cli-nodejs}`, `.local/share/{Steam,containers,direnv,flatpak,keyrings,Trash,uv}`, `.local/state/noctalia`, `.local/bin`, `.cache/{bun,uv,ms-playwright}`, `.var/app` (Flatpak user data), mail/editor/game/toolchain dirs (`.thunderbird`, `.vscode*`, `.steam`, `.m2`, `.gradle`, `.android`, `.bun`, `.cargo`, `.rustup`, `.duckdb`, `.copilot`, `.abacusai`, `.gemini`), and `{ .gnupg, .ssh }` with `mode = "0700"`.
- **User file**: `.config/zsh/.zsh_history`

**If you add an app that stores state in `$HOME`, you must add its directory to that list, or the state vanishes on the next reboot.** Watch for `.config/<NewApp>`, `.local/share/<NewApp>`, `.cache/<NewApp>`. Some entries are leftovers from removed apps (e.g. `.config/Code`, `.config/Antigravity`, `.config/xfce4`); pruning them is safe but out of scope unless asked.

### Credentials (do not break)

- `users.mutableUsers = false` and `users.users.fumoctl.hashedPasswordFile = "/persist/passwords/fumoctl"`.
- The password hash lives **inside `/persist`** so it survives the root wipe. It is created manually at install time (README §4): `mkdir -p /mnt/persist/passwords`, `mkpasswd -m sha-512 | tee /mnt/persist/passwords/fumoctl`, `chmod 600`.
- **Never** commit a password hash, and never point `hashedPasswordFile` at a path outside `/persist`, or the user is locked out after the first boot.
- `home-manager.backupFileExtension = "backup"`: when a file is not yet a Home Manager symlink, HM moves it to `<name>.backup` before linking. Existing `.backup` files are expected and harmless.

## 7. Desktop stack (Hyprland + Noctalia)

### Hyprland

- NixOS side: `programs.hyprland = { enable = true; xwayland.enable = true; withUWSM = true; }` (no extra Hyprland plugins).
- HM side (`home/noctalia.nix`):

  ```nix
  wayland.windowManager.hyprland = {
    enable = true;
    configType = "lua";                     # Hyprland 0.55+ native Lua config (liblua 5.5)
    extraConfig = builtins.readFile ./hyprland.lua;
  };
  ```

  This generates `~/.config/hypr/hyprland.lua` plus `~/.config/hypr/.luarc.json` (pointing the editor LSP at the Hyprland Lua stubs). **`home/hyprland.lua` is only picked up through this `readFile`** — renaming or moving it silently drops the entire window manager config, and switching to `settings` would emit the legacy format instead.

- `home/hyprland.lua` essentials:
  - `hl.env(...)` sets `QT_QPA_PLATFORMTHEME=kde` and cursor `Bibata-Modern-Ice` size 24 (`XCURSOR_*`/`HYPRCURSOR_*`).
  - `hl.on("hyprland.start", ...)` launches `noctalia`, imports env into systemd/dbus, and starts `equibop -m` + `steam -silent`.
  - Monitors: one generic rule (`output = ""`, preferred, auto).
  - `general`: gaps 5/10, border 2, dwindle. `decoration`: rounding 12, blur on, opacity 0.94/0.88.
  - Input: `us`/`altgr-intl`, `lv3:ralt_switch` — keep in sync with `services.xserver.xkb`.
  - Layer rules: `noctalia` and `gtk-layer-shell` get blur.
  - Binds: Super+Return (ptyxis), Super+E (thunar), Super+B (brave), Super+Q close, Super+M exit (`hyprshutdown` if present, else `hyprctl dispatch exit`), Super+F fullscreen, Super+Shift+V float, Super+P pseudo, Super+J togglesplit, Super+Space/V/S/comma (Noctalia launcher/clipboard/control-center/settings), Alt+Tab (`window-switcher`), Super+Shift+S / Super+Shift+Ctrl+S (Noctalia screenshots), focus/workspace binds 1–9, mouse drag/resize, XF86 media/brightness keys.
  - **Known dead stub:** `hl.device({ name = "<YourMouseName>", ... })` is a leftover placeholder. It is harmless but should be given a real device name (from `hyprctl devices`) or removed. Don't imitate it in new code.
  - Prefer Noctalia IPC (`noctalia msg …`) for shell features in binds; see the noctalia input's `docs/user/ipc/` for the full command list.

### Noctalia (shell + bar)

- System (`hosts/common.nix`): `programs.noctalia = { enable = true; recommendedServices.enable = true; }`. The noctalia flake's NixOS module **disables** the nixpkgs noctalia module (`disabledModules`), and `recommendedServices` applies `mkDefault` for NetworkManager, Bluetooth, UPower, and power-profiles-daemon.
- HM (`home/noctalia.nix`):
  - `programs.noctalia = { enable; systemd.enable; settings = { theme.templates.builtin_ids = [ "gtk3" "gtk4" "kcolorscheme" ]; wallpaper.enabled; settings.plugins.enabled = [ "elijaharch/wl-screen-mirror" ]; }; }`
    → generated `~/.config/noctalia/config.toml`, validated at build time by `noctalia config validate`.
  - `~/.config/noctalia/noctconf.toml` (symlink to `home/noctalia.toml`, set via `home.file`) holds the hand-written bar/widget/theme TOML. Noctalia reads **every `*.toml`** in `~/.config/noctalia/` alphabetically and merges them, so `config.toml` (Nix-declarative) and `noctconf.toml` (hand-edited) coexist. The filename is arbitrary; keep the pattern (`config.toml` = Nix, `noctconf.toml` = hand edit).
  - Bar layout, the Tokyo-Night palette, widget scales, and the `elijaharch/wl-screen-mirror` mirror widget live in `noctalia.toml`.
  - Runtime GUI overrides go to `~/.local/state/noctalia/settings.toml` (**persisted** via `.local/state/noctalia`) and **win over** the declarative config. If a declarative change "does nothing", check that file.
  - Service: `~/.config/systemd/user/noctalia.service`, `WantedBy/PartOf/After graphical-session.target` (the HM `wayland.systemd.target` default), `X-Restart-Triggers` on the generated config. `home/hyprland.lua` also launches `noctalia` at session start — see §12, item 3.

### Theming glue

- GTK: `adw-gtk3-dark`, icon theme `breeze` (`kdePackages.breeze-icons`), cursor `Bibata-Modern-Ice` 24 (`home.pointerCursor` with gtk + hyprcursor).
- Qt: `qt.platformTheme.name = "kde"` + `QT_QPA_PLATFORMTHEME=kde`; `kdePackages.qt6ct` (HM) and `kdePackages.plasma-integration` (pulled in by HM `qt`).
- Extra HM packages for Noctalia hooks: `adw-gtk3` (theme lookup), `glib` (`gsettings`, used by the GTK apply hook).
- Noctalia's template system generates GTK3/GTK4/KColorScheme CSS from the palette; templates are enabled via `theme.templates.builtin_ids`.
- `documentation.man.cache` and `fonts.fontconfig.defaultFonts` (JetBrainsMono NF / Noto CJK JP) are set system-wide; `nerd-fonts.*`, `noto-fonts{,-cjk-{sans,serif},-color-emoji}`, `ipafont`, `kochi-substitute`, and `liberation_ttf` are installed. Fonts referenced in `hyprland.lua`/`noctalia.toml` (`JetBrainsMono NF Medium`) must come from these packages.

## 8. XDG portals (read the inline note before touching)

```nix
xdg.portal = {
  enable = true;
  wlr.enable = false;
  extraPortals = [ pkgs.xdg-desktop-portal-hyprland pkgs.xdg-desktop-portal-gtk ];
  config.common.default = [ "gtk" ];
  config.hyprland.default = [ "hyprland" "gtk" ];   # NOT just ["hyprland"]
};
```

The `hyprland` section overrides `common` for **all** interfaces when `XDG_CURRENT_DESKTOP=Hyprland`. The Hyprland portal only implements Screenshot/ScreenCast/GlobalShortcuts, so `gtk` must stay in the list, or `org.freedesktop.portal.Settings` disappears and libadwaita apps (Ptyxis) always render in light mode. This comment exists in `common.nix` — preserve it.

Session env vars (`environment.sessionVariables`): `NIXOS_OZONE_WL=1`, `MOZ_ENABLE_WAYLAND=1`, `XDG_CURRENT_DESKTOP/SESSION_DESKTOP=Hyprland`, `XDG_SESSION_TYPE=wayland`, `QT_QPA_PLATFORM="wayland;xcb"`, `QT_WAYLAND_DISABLE_WINDOWDECORATION=1`, `GDK_BACKEND="wayland,x11,*"`, `SDL_VIDEODRIVER=wayland`, `CLUTTER_BACKEND=wayland`.

## 9. Networking, DNS, VPN, firewall

- `networking.nftables.enable = true`; `firewall.enable = true`, `checkReversePath = "loose"`, trusted interfaces `tun0`, `tun2`, `amn0` (+ `lo`).
- NetworkManager with `dns = "systemd-resolved"`, ignoring DHCP-provided DNS (v4/v6), stable-temporary MACs, IPv6 privacy `2`, random scan MAC.
- `services.resolved` (systemd, **not** unbound — `services.unbound.enable = false`): DNSSEC on, DNSOverTLS on, AdGuard DNS primary, Quad9 + Mullvad fallbacks, `Domains = [ "~." ]`.
- `programs.amnezia-vpn` (from the unstable overlay) is the VPN. WireGuard/OpenVPN trust is expressed via `trustedInterfaces`, not `allowedUDPPorts`.
- `services.tzupdate.enable = true` — **this overrides `time.timeZone`.** `common.nix` sets `time.timeZone` via `lib.mkDefault "America/Argentina/Buenos_Aires"`, but the evaluated `config.time.timeZone` is `null` and the machine follows the IP-derived zone (`America/Asuncion` at last observation). Do **not** rely on `time.timeZone`; if a fixed zone is required, disable tzupdate and set the option unconditionally.
- `programs.captive-browser` is laptop-only, bound to `wlp98s0`.

## 10. Virtualisation and containers

`hosts/containers.nix` (shared) + `hosts/<host>/containers.nix` (host-specific, merged by the module system):

- **Docker** (rootful, `autoPrune.enable = true`) and **Podman** (rootless, `defaultNetwork.settings.dns_enabled = true`) are both enabled.
- **Critical invariant:** `virtualisation.podman.dockerCompat = false` and `dockerSocket.enable = false`. Never enable them — the `docker` CLI and `/var/run/docker.sock` must keep pointing at dockerd (verified: the `oci-containers` backend is `podman`, while Docker owns the real socket).
- `virtualisation.containers.storage.settings.storage.driver = "overlay"`.
- `virtualisation.oci-containers.backend = "podman"` with shared container `yugabyte` (`docker.io/yugabytedb/yugabyte:latest`, `autoStart = false`, `--network=host`, volume `yugabyte-data:/home/yugabyte/var:Z`, runs as user `fumoctl`). It was fiddly to get right — don't change `cmd`/`extraOptions` without running it.
- Tools: `kind`, `kubectl`, `helm`, `k9s`, `skopeo`, `dive`, `distrobox`, `podman-desktop`, `docker-compose`, `podman-compose`, `fuse-overlayfs`, `shadow` (newuidmap/newgidmap).
- **libvirt** (QEMU/KVM, `runAsRoot = true`, `swtpm` for TPM, `virtiofsd`) + `virt-manager` + `spice-vdagentd` + Steam remote-play/dedicated-server firewall openings. This is why `nix-ld.libraries` carries the long X11/GL/audio library list (emulators and Flutter/Qt apps built outside Nix).

When adding a container: shared/common services go in `hosts/containers.nix`; per-machine ones go in `hosts/<host>/containers.nix` using the commented template. Keep `autoStart` explicit (the shared default here is `false`).

## 11. Nix daemon settings and local commands

```nix
nix.settings = {
  experimental-features = [ "nix-command" "flakes" ];
  trusted-users = [ "root" "@wheel" ];
  auto-optimise-store = lib.mkDefault true;
  substituters = [ cache.nixos.org noctalia.cachix.org nyx-cache.chaotic.cx ];
  trusted-public-keys = [ ... ];
};
```

NixOS appends to `substituters` rather than replacing the default, so `/etc/nix/nix.conf` lists `cache.nixos.org` and `nyx-cache` **twice** (verified). That is expected and harmless — don't add `mkForce` just to de-duplicate.

```bash
# Build/switch
sudo nixos-rebuild switch --flake .#fumonix-desktop
sudo nixos-rebuild switch --flake .#fumonix-laptop
sudo nixos-rebuild boot   --flake .#fumonix-desktop   # apply at next boot (safer for initrd/impermanence changes)

# Evaluate only (fast sanity check)
nix eval .#nixosConfigurations.fumonix-desktop.config.system.build.toplevel.drvPath

# Single option
nix eval --raw .#nixosConfigurations.fumonix-desktop.config.services.displayManager.defaultSession

# Home Manager option value
nix eval --json .#nixosConfigurations.fumonix-desktop.config.home-manager.users.fumoctl.programs.git.signing

# Formatting / editor tooling
nixfmt $(git ls-files '*.nix')
nixd          # LSP, installed system-wide

# Update one input
nix flake update noctalia --flake .#fumonix-desktop
```

> If `nix eval` fails with `attempt to write a readonly database (... fetcher-cache-v4.sqlite)`, the sandboxed/agent environment has a read-only XDG cache. Work around it with a private cache dir: `XDG_CACHE_HOME=$(mktemp -d) nix --offline eval …`.

## 12. Known quirks and traps (do not "fix" blindly)

These were found by evaluating the flake; treat them as the current state of the repo, not as instructions to change them during an unrelated task.

1. **`flake.lock` is dirty relative to its own description.** The `nixpkgs` node resolves to a *nixos-unstable* tarball while `flake.nix` says `nixos-26.05`, and the generated system name reads `26.05.20261021.da6dc0e`. If a task is about pinning/release hygiene, raise it; otherwise leave it.
2. **`programs.noctalia.systemd` (system) is not enabled** — only the HM user service is. Don't assume a system-level noctalia unit exists.
3. **Noctalia is started twice on paper:** the HM user service (`WantedBy=graphical-session.target`) and `hl.exec_cmd("noctalia")` in `hyprland.lua`. Noctalia is single-instance in practice, but if you touch either, verify the session still starts (a duplicated launcher is the most likely cause of a "shell won't start"/"two bars" report).
4. **Two Noctalia config sources:** `~/.config/noctalia/config.toml` (from `programs.noctalia.settings`) and `~/.config/noctalia/noctconf.toml` (from `home.file`) are merged by Noctalia. Before editing a key, check which of the two (or `~/.local/state/noctalia/settings.toml`) actually owns it.
5. **`home/shell.nix` SSH config uses an `onChange` hook.** `~/.ssh/config_source` is a HM file; on change it is copied to `~/.ssh/config` (chmod 600) because HM cannot produce a 600 symlink. SSH keys themselves are **not** managed by Nix (they live in persisted `~/.ssh`). `programs.gh` uses the renamed `gitCredentialHelper.enable` (HM prints an "obsolete option renamed" trace — the current spelling works).
6. **Git commit signing is enforced** (`signing.key = "35FAC098F119E8FA"`, `signByDefault = true`, tags signed). Commits made without the private key/`gpg-agent` will fail; that is by design, not a repo bug.
7. **Flatpak is managed from Home Manager** via `inputs.nix-flatpak.homeManagerModules.nix-flatpak`, while the NixOS module is also loaded and `services.flatpak` is enabled system-wide with `uninstallUnmanaged = false`. User apps (Flatseal, OBS, Bottles, ProtonPlus, protontricks, DistroShelf) are installed by HM with a daily auto-update timer. Four `home.activation` hooks apply flatpak overrides: language `en;ja`, OBS (clearing `QT_PLUGIN_PATH`/`LD_LIBRARY_PATH`/`QT_QPA_PLATFORM_PLUGIN_PATH`), Bottles (`home` filesystem), and theme sharing (read-only `/nix/store` plus GTK theme/icon/config dirs). `.var/app` and `~/.local/share/flatpak` are persisted.
8. **`home.activation` hooks that interpolate `pkgs` must run after `writeBoundary`** (they do, via `lib.hm.dag.entryAfter [ "writeBoundary" ]`).
9. **`hardware-configuration.nix` is generated** by `nixos-generate-config`; hand-edit only the kernel-module lists (as both files do) and never re-add `fileSystems` (disko owns them).
10. **`dotfiles/wallpaper.png` is unused**; Noctalia wallpapers are managed by the shell (`.local/state/noctalia` is persisted).
11. **`inputs.nur` is declared but unused.** Referencing `inputs.nur` from a module works (it is in `specialArgs`), but nothing does today.
12. **`system.stateVersion = "26.05"` and `home.stateVersion = "26.05"`** — do **not** bump these to silence warnings; they gate migrations. Changing them rewrites user state.
13. **`pkgs.unstable` is an overlay attribute, not `pkgs.nixpkgs-unstable`.** Don't import `inputs.nixpkgs-unstable` inside modules; use `pkgs.unstable.*`.
14. **`hardware.graphics.extraPackages` is declared twice** (empty list in `common.nix`, AMD VA-API packages in `desktop/default.nix`). Lists concatenate, so both apply on the desktop; the laptop gets only the empty base.
15. **No noctalia plugin mirror packaging:** the `elijaharch/wl-screen-mirror` plugin is fetched at runtime by Noctalia (community source), so its state lives under `~/.local/state/noctalia` and `~/.local/share/noctalia` — the former is persisted, the latter is not. A rebuild does not install the plugin.

## 13. Conventions for changes

**Style**

- Nix code is formatted with `nixfmt` (RFC-style, as in `flake.nix`). `nixpkgs-fmt` is also installed, but the repo follows `nixfmt`; a few files currently do **not** pass `nixfmt --check` (`home/noctalia.nix`, `hosts/common.nix`, `hosts/containers.nix`, both `hosts/*/containers.nix`, both `hosts/*/disko.nix`, `hosts/laptop/default.nix`). If you touch one of those files, format the whole file in the same commit.
- Keep the `{ config, lib, pkgs, inputs, ... }:` function header (or the subset actually used) in every module; `inputs` is always available.
- Section headers are `# --- Foo ---`. Explanatory comments (especially the portal, keyring, and podman ones) explain *why* and must be preserved when editing nearby lines.
- Prefer `lib.mkDefault` for anything a host may override (kernel, secure boot, timezone, Bluetooth, UPower, PPD).
- Never hard-code the absolute path of a package binary in HM activation or scripts — use `${pkgs.foo}/bin/foo` or `lib.getExe`.

**Hardware-specific vs shared**

- Both machines import `hosts/common.nix`; anything depending on AMD desktop vs TUXEDO laptop hardware goes in `hosts/<host>/default.nix`.
- Kernel selection uses `if pkgs ? linuxPackages_cachyos-lto-znver4 then … else pkgs.linuxPackages_latest` — keep that guard for portability.
- NVIDIA (laptop) uses `nvidia_cachyos-lto` when available, `open = true`, fine-grained power management, and PRIME offload with fixed PCI bus IDs (`amdgpuBusId = "PCI:66:0:0"`, `nvidiaBusId = "PCI:64:0:0"`). If the hardware changes, re-derive these from `lspci`.

**Adding things**

| Goal | Where |
|---|---|
| System-wide CLI/desktop app | `environment.systemPackages` in `hosts/common.nix` |
| User-only app | `home.packages` in `home/shell.nix` (general) or `home/noctalia.nix` (shell/theming deps) |
| Unstable app | prefix with `unstable.` |
| System service | `hosts/common.nix` (or the host file) |
| User service / dotfile | `home/*.nix` (`systemd.user.services`, `home.file`, `xdg.configFile`) |
| New app with `$HOME` state | also add the dir to `environment.persistence."/persist".users.fumoctl.directories` |
| New OCI container | `hosts/containers.nix` (shared) or `hosts/<host>/containers.nix` |
| New Flatpak | HM `services.flatpak.packages` in `home/shell.nix` |
| New Hyprland bind/rule | `home/hyprland.lua` (Lua `hl.` API) |
| New bar widget / palette | `home/noctalia.toml` (and enable plugins under `programs.noctalia.settings.settings.plugins.enabled` in `home/noctalia.nix`) |
| New MIME association | `xdg.mimeApps.defaultApplications` in `home/shell.nix` |
| New input device | `hl.device({ name = "<real name>", ... })` in `hyprland.lua` + `services.libinput` in `common.nix` |

**Working with the desktop config**

- Changes to `home/hyprland.lua` or `home/noctalia.toml` need a rebuild; because HM is embedded in the system, `nixos-rebuild switch` handles it.
- Hyprland/Noctalia breakage is usually caused by: malformed Lua (the whole config is one `readFile`), a noctalia config that fails `noctalia config validate` (which fails the HM generation), or a missing font/icon/theme package.
- On the laptop, GPU switching problems are more likely than config problems (`powerManagement.finegrained`).

**Committing**

- Commit messages here are short and often joking ("yugabyte final fix geez", "update + vscodium"). Match the terse style; do **not** add "Generated with …" trailers or co-author lines unless asked.
- Commit `flake.lock` whenever you change `flake.nix` inputs.
- Conventional-commit prefixes are **not** used here.

## 14. Verification checklist

Always do these before saying a change is done (never claim a config is valid without evaluating it):

```bash
# 1. Repo hygiene: no stray files, no accidental secret
git status --short && git diff

# 2. Syntax/format (nixfmt on files you touched)
nixfmt --check <file>

# 3. Fast evaluation of BOTH hosts (no build)
nix eval --raw .#nixosConfigurations.fumonix-desktop.config.system.build.toplevel.drvPath

# 5. Full build (slow; requires network + caches)

```

Sandboxed agents: if `nix eval` fails on the read-only fetcher cache, use `XDG_CACHE_HOME=$(mktemp -d) nix --offline eval …`. If `nixos-rebuild` cannot be run, say so explicitly instead of implying it was tested.

## 16. Installing DeepSeek Harness (`dsh`) plugins

`dsh` comes from the `dsh-nix` input (`github:fumoctl/dsh-nix`). Its Home Manager module is imported in `home/shell.nix` (`inputs.dsh-nix.homeManagerModules.dsh`) and configured under `programs.dsh`. **Install plugins declaratively there. Do not run `dsh plugin ...` imperatively.** The module replaces dsh's activation-time pnpm reconcile with a build-time one, so removals are declarative and resolution failures show up at `nix build`.

### Plugin kinds

`profiles.<name>.plugins` is an **ordered** list, and order is the layer order in `dsh.profile.bundles`. Each entry's kind is inferred from its shape:

| Kind | Example | Resolution |
|---|---|---|
| In-box bundle | `"@deepseek-ai/dsh-base"` | Name only. Shipped with `pkgs.dsh`, nothing is fetched. |
| pnpm spec (any other string) | `"github:someone/cool-plugin"` | A fixed-output derivation runs `pnpm add` at build time. Pin it with `specsHash`. |
| Nix path or package | `./my-plugin`, `pkgs.fetchFromGitHub { ... }`, `plugins.mkPluginBundle { ... }` | Symlinked into `node_modules/<packageName>` with its own dependency closure. `packageName`s must be unique. |

In-box bundles are `@deepseek-ai/dsh-base`, `@deepseek-ai/dsh-web-app` and `@deepseek-ai/dsh-headless`. `dsh-web-app` and `dsh-headless` need `dsh-base` listed first.

### Steps

1. Edit the `programs.dsh` block in `home/shell.nix`. Add the plugin to an existing profile, or add a new one:

   ```nix
   programs.dsh = {
     enable = true;
     profiles.web = {
       plugins = [ "@deepseek-ai/dsh-base" "@deepseek-ai/dsh-web-app" ];
     };
     profiles.custom = {
       plugins = [
         "@deepseek-ai/dsh-base"
         "github:someone/cool-plugin"   # pnpm spec
         ./my-plugin                    # local dir with package.json
       ];
       specsHash = "";                  # discovery mode, see step 2
       # userPatchesFile = ./patches.yml;   # optional profile-level cordis.patch.yml
     };
     # homePatchesFile = ./home-patches.yml;  # -> ~/.dsh/cordis.patch.yml
   };
   ```

2. **pnpm specs only:** leave `specsHash = ""`, run a build, and copy the real hash from the "got: sha256-…" error into `specsHash`. One hash covers every spec in the profile. Changing a spec means updating the hash again.
3. Apply it: `sudo nixos-rebuild switch --flake .#<hostname>` (see §11). Activation materialises each immutable profile into `~/.dsh/profiles/<name>`.
4. Run it with `dsh --profile <name> ["task"]`. The web profile serves `http://127.0.0.1:3080`.

### Bundled plugins that are not in-box bundles (e.g. `@deepseek-ai/dsh-mcp-client`)

Some official packages, such as `@deepseek-ai/dsh-mcp-client`, are **already inside the pinned `dsh` install**. They are Cordis plugins with no `dsh.bundle` field, so they are not `plugins` entries and need no `specsHash`. Adding the bare npm name as a spec would pull `latest` (`0.0.1-rc.1`), which does not match the pinned dsh `0.2.1-rc.2`. Enable one through the Home Manager module's per-profile `userPatches` option in `home/shell.nix`. It takes one `insert` entry per MCP server:

```nix
programs.dsh.profiles.web = {
  plugins = [ "@deepseek-ai/dsh-base" "@deepseek-ai/dsh-web-app" ];
  userPatches = [{
    insert = [{
      id = "mcp-memory";
      name = "@deepseek-ai/dsh-mcp-client";
      config = {
        serverName = "memory";      # unique, [A-Za-z0-9_-]{1,32}; tools become mcp__memory__*
        transport = "stdio";        # or "streamable-http" (url/headers)
        command = "${pkgs.nodejs}/bin/npx";
        args = [ "-y" "@modelcontextprotocol/server-memory" ];
      };
    }];
  }];
};
```

- `home/shell.nix` shares one `mcpPatches` list across the `headless`, `web` and `tui` profiles, and currently enables the `dbcode` (CLI bundled in the VSCodium DBCode extension, newest installed version) and `rivalsearch` (remote `https://RivalSearchMCP.fastmcp.app/mcp`) servers.
- `userPatches` is JSON-serialisable only, so `!!js` (for example `process.env.GITHUB_TOKEN`) does not work there. For servers that need secrets in `env`, use `userPatchesFile = ./patches.yml;` or `homePatchesFile`.
- Use a stdio `command` by absolute store path. dsh does not run a package manager, and stdio `env` is merged over a scrubbed ambient env. Never commit tokens.
- Verify with `nix flake check`, then run `dsh --profile web` and look for the `mcp__<serverName>__*` tools.

### Writing a local plugin

A plugin joins the layer list only if its `package.json` declares a patch. Otherwise it is just a dependency in `node_modules`.

```jsonc
// package.json
{
  "name": "@me/my-plugin",
  "type": "module",
  "exports": { "./plugin": "./plugin.mjs" },
  "dsh": { "bundle": { "patch": "cordis.patch.yml" } }
}
```

```yaml
# cordis.patch.yml
- insert:
    - id: my-plugin
      name: ./node_modules/@me/my-plugin/plugin.mjs
      config: { }
```

`plugin.mjs` exports `apply(ctx, config)`.

### Repo-specific notes

- The module owns the profile composition under `~/.dsh/profiles/<name>`, while preserving runtime settings, custom providers, and custom models (`{ id, name, config }` entries written by DSH into `~/.dsh/profiles/<name>/cordis.patch.yml`) across profile rebuilds by merging them with Nix's `userPatches`. Sessions and credentials (`~/.dsh/sessions`, `~/.dsh/.credentials.yaml`) belong to the app.
- Impermanence: `.dsh`, `.dsh-tui` and `.agents` are in `environment.persistence` in `hosts/common.nix`. A plugin that stores state elsewhere in `$HOME` needs that path added there (§5).
- Credentials: set `DEEPSEEK_API_KEY`, or configure the model in the web UI. Never commit keys.
- Verify with `nix flake check` and an evaluate-only build of the host (§14). The `dsh-nix` repo also provides `checks.profile-boot-web` and `checks.profile-boot-headless`, which boot a composed profile inside the Nix sandbox. A broken composition fails `nix build`, not at runtime.
- The `dsh-nix` input currently has no `nixpkgs.follows` (see the lockfile note in §4); don't add one unless asked. Its default `pkgs.dsh` build needs `fetchPnpmDeps` and `pnpmConfigHook` from nixpkgs.
- Upstream ships no TUI profile, only `web` and `headless`. `home/shell.nix` defines `profiles.tui` using `@deepseek-harness-tui/dsh-tui@0.16.1`.
